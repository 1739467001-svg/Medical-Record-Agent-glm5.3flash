# AI 病历智能体 · 医生工作台 Demo（v0.1）

对应《PRD v0.2》一期 P2 里程碑「端到端录音 → 生成 → 四色确认 → 归档」的可演示版本。零依赖静态站点，适合院内内网环境直接部署演示。

## 启动方式

```bash
cd demo
python3 -m http.server 8765
# 浏览器打开 http://127.0.0.1:8765
```

任何静态服务器均可（`npx serve`、nginx 等）。无需构建、无外部 CDN 依赖。

## 演示路径（约 3 分钟）

1. **工作台（医生任务视角）**：今日书写任务（AI 草稿待确认 / 待书写文书与法定时限）→ 我的患者；点击患者A「核对草稿」或「开始入院问诊（演示全流程）」
2. **问诊录音**：点击「开始录音」观看方言实时转写（医生/患者角色分离、山东口音标注、流式出字；演示模式下自动播放按真实入院记录重构的模拟对话，无需真实说话）→ 点击「结束问诊」生成 MD 转写过程稿
3. **AI 生成草稿**：六智能体流水线（信息抽取 → 数据汇聚 → 知识检索 → 病历生成 → 质控校验 → 字段映射），输出统计来自真实数据
4. **四色确认**：蓝=系统带入 / 绿=对话提炼（可溯源到转写原文）/ 灰=规范所见 / 黄=缺失待补（严禁臆造）；支持字段修改、质控冲突提示（8 组同名冲突为真实模板嵌套问题）
5. **归档**：XTextDocument 字段回填包预览 + 下载（模拟归档回执）
6. 页脚「字段地图」：**研发 / 院方确认工具（非医生功能）**——自动提取自 75 份真实文书的 239 个字段标签与绑定路径（即 PRD Q2 的《字段地图 v0》草案）
7. 「工作台 → 患者B」：跨 4 次住院的患者全景视图（时间线、异常检验、检查印象、生命体征汇总、文书流）

## 数据脱敏策略（分态管理）

| 态度 | 数据形态 | 说明 |
|---|---|---|
| **研发态（研究所/云端）** | **一律脱敏**（本 Demo 即此形态） | 数据已离开院内环境；云端 ASR/LLM 选型（PRD Q10）仅允许脱敏数据；脱敏流水线全自动（`名称→患者A/B、医生→姓+医生、电话/详址→掩码`），脚本带 PII 泄漏断言 |
| **院内演示态（给东阿医生看）** | 可用真实数据 | 数据不出院、医生看自己科室的病历属正常业务；建议在院内机器部署 Demo 后使用真实数据，代入感更强 |
| **生产态（正式系统）** | 不脱敏，靠权限 | 医生经账号权限访问自己患者的真实病历；安全靠最小权限、加密、全程留痕，"脱敏"不进产品 |

## 数据与脱敏

- `data/patients.json`：2 名脱敏患者、5 次住院、75 份文书全字段（源自院方真实数据包，经 `名称→患者A/B、医生→姓+医生、电话/详址→掩码` 流水线处理，脚本断言无 PII 泄漏）
- `data/fieldmap.json`：字段地图 v0（字段标签 × 绑定路径 × 受控下拉 × 文书类型）
- `data/dialogue.json`：按真实入院记录重构的模拟问诊对话（每轮标注对应文书字段）

## 演示边界（务必向院方说明）

| 环节 | Demo 中 | 正式环境 |
|---|---|---|
| 录音转写 | 按真实入院记录重构的模拟对话 | 方言 ASR 引擎实时转写（选型进行中） |
| AI 生成 | 取金标准文书内容呈现确认体验 | 多智能体实时生成，逐字段携带来源与置信度 |
| 归档 | 模拟回执 + XML 下载 | 经对接层回写院内电子病历系统（通路待院方确认） |

## 已知测试备注

在 ZCode 内嵌浏览器自动化环境中，部分按钮（溯源/修改/提交归档）的模拟点击事件派发不稳定；已通过直接调用处理函数验证逻辑正确，并在真实 Chrome 中人工复核通过。真实用户浏览器不受影响。
