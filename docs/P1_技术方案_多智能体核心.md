# P1 技术方案设计文档 · 多智能体核心（v1）

> 对应 PRD 4.3/13 章：PRD v1.0 开发基线下的首个技术方案文档。状态：**已实现并上线**（GitHub r c1fb87c = 云服务器）。

## 1. 架构

```
orchestrator（DAG 编排，全程 trace）
 ├─ extractor   LLM   转写稿 → 医学要素（带对话轮次出处，无录音则跳过）
 ├─ aggregator  代码  HIS 视图/patients.json → 标准化数据集（VISIT 过滤/日期归一/异常标记）
 ├─ retriever   代码  本院脱敏语料检索同类写法 + 文书规范要点（v1 关键词，二期向量）
 └────→ writer  LLM   要素+数据+知识 → 草稿字段（蓝/绿/灰来源+依据+置信度，受控码绝不猜测）
        └─→ qc  双层  代码硬校验（生理范围/HIS 交叉核对/受控码拦截）+ LLM 复核（逻辑矛盾/过度推断）
            └─→ mapper 代码  草稿 → 模板填充包（label→binding 字段地图，模板外标记）
```

- 六个智能体 = **三次真实 LLM 调用**（extractor/writer/qc-复核）+ **三个纯代码组件**（aggregator/retriever/mapper——用 LLM 反而是错误设计）。
- 每个字段携带 `{label, value, source, basis, confidence, binding}`——四色确认的元数据由此而来。
- 降级哲学：任何智能体失败只降级自身（writer 失败仍有蓝/灰规则字段），流水线永不整体崩。

## 2. 关键实现决策

| 决策 | 理由 |
|---|---|
| writer 按字段产出而非自由作文 | 字段级才能溯源、才能被 QC 逐条拦截、才能对准模板绑定 |
| QC 分两层 | 代码层零成本零幻觉（数值范围/交叉核对）；LLM 层抓医学语义（实测拦下"病理结果当临床依据"的过度推断） |
| retriever v1 用关键词检索 | 诚实：先跑通链路，检索质量二期用向量库升级；语料=本院脱敏金标准文书 |
| 无录音模式 transcript=None | extractor 直接跳过——系统从第一天就按"录音是增强而非前提"设计 |
| 密钥仅服务器 `.llm_env` | 约8.2 数据安全规约；送 LLM 内容经 sanitize() 兜底脱敏 |

## 3. 评测结论（evaluation/评测报告_multiagent.md）

**入院记录（患者A 行，覆盖率 H/G）：**

| 生成器 | 覆盖率 | 说明 |
|---|---|---|
| 规则版 v0 | 5% | 仅 HIS 直填 |
| 单提示词 LLM v1 | 10% | 无结构化流程 |
| **多智能体 v1** | **13%** | 六智能体流水线 |

- 模式B（模拟对话恢复率验证）：extractor 抽出 22 项要素 → writer 完整还原主诉/现病史/既往史/个人史/婚育史/家族史六节，QC 零拦截——**"有录音能到什么水平"的首次实证**。
- 全库 36 份三方数据见报告；多智能体的增量主要来自 writer 的规范化归纳与 QC 的错误拦截。
- 诚实边界：覆盖率的天花板仍由录音依赖度（54~67%）决定，多智能体优化的是"可推导部分的质量与可追溯性"。

## 4. 服务端接口

- `POST /mra/api/generate-draft`（NDJSON 流式）：`agent_start`/`agent_done`（真实耗时+摘要+QC 警告）→ `final`（字段包+stats+trace）。前端流式点亮。
- 白名单入参（code+admission）、提示词固定服务端、限流共享、密钥服务端隔离。

## 5. 后续迭代（P1 剩余 → P2）

1. retriever 向量化（本院文书 embedding）→ writer few-shot 文风对齐 → 诊断字段准确率提升；
2. 首次病程/出院记录的专用 writer 提示词（鉴别诊断知识辅助）；
3. 录音到位：ASR MCP → 真实转写稿 → 模式B 变生产模式；
4. 质控规则库按院方质控制度扩充（Q3）。
