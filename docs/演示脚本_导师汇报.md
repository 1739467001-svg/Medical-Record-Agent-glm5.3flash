# 演示脚本 · 导师汇报（10~15 分钟）

> 适用：向导师/课题评审汇报项目进展与阶段性成果。
> 与 `docs/演示脚本_5分钟.md` 的区别：那份面向**院方**（讲业务流程与合规责任），本份面向**导师**（讲技术路线、工程完成度、数据与方法、下一步规划）。
> 原则：**先给结论，再给证据，最后给规划**；每个演示环节都有降级预案，任何环境故障不冷场。

---

## 一、演示形式（三选一，推荐第 1 种）

| 形式 | 做法 | 适用 | 优点 / 风险 |
|---|---|---|---|
| **① 现场投屏实操（推荐）** | 笔记本接投影，Chrome 全屏，按第二部分的动线一步步点 | 面对面汇报、导师在办公室/会议室 | 真实感最强、可随时回答追问；**风险是网络/服务故障**，必须准备 §五 降级预案 |
| ② 录屏 + 讲解 | 提前录好 8~10 分钟操作视频，现场边播边讲 | 时间紧、场地网络不可靠 | 零故障风险；但无法现场应答追问，需额外准备截图/数据页兜底 |
| ③ 纯文档/PPT 汇报 | 只讲架构图、数据与结论，不实操系统 | 组会、多人评审、时间 5 分钟以内 | 高效；但"能跑"这件事说服力弱，建议至少留 2 分钟实机演示 |

**建议组合**：现场实操 10 分钟 + 数据结论 3 分钟 + 规划 2 分钟。若时间只有 5 分钟，用形式②并把重点放在"真实案例跑通 + 量化结论"。

### 如果采用形式②，录屏建议顺序
1. 公网地址打开工作台 → 登录 → 患者F 任务卡（0:00–1:00）
2. 进入问诊 → 播放真实录音转写稿 → 结束问诊 AI 生成（1:00–3:00）
3. 四色确认页慢速讲解（重点，3:00–6:00）
4. 提交归档 → 打印/存 PDF（6:00–7:00）
5. 切换上级医师审签 → 质控科抽查与审计日志（7:00–9:00）
6. 修改回流页签（9:00–10:00）

## 三、演示动线（10~15 分钟）

### 0:00–1:30 开场：三句话定位（不操作系统）

1. **「这是一个从方言语音到规范病历的端到端系统。」**——医生口述/医患对话录音进，符合医院模板的病历草稿出，中间有 AI 生成与质控，最后必须医生确认才归档。
2. **「核心不是模型，是工程与数据闭环。」**——六智能体编排、四色溯源、审签质控、修改回流、数据飞轮，模型（ASR/LLM）全部可插拔。
3. **「已经在真实方言录音上跑通了全链路。」**——患者F 是贵院设备采集的 93.7 秒真实术前问诊，本地转写、脱敏接入，全流程真实运行。

> 汇报口径建议：先讲"做了什么、到哪一步"，再讲"为什么这么做"，最后讲"下一步"。

### 1:30–2:30 工作台与问诊入口（登录住院医师）

- 工作台：指出**法定时限标注**（入院记录 24h、首程 8h）、待办统计、患者F 的绿色「真实录音」标签。
- 点患者F「进入问诊流程」→ 录音页：点「开始录音」→ 播放**真实问诊转写稿**（50 轮，山东方言口音）。
- **话术**：「这段文本来自真实录音。方言同音错字（如'消炎针'被听成'小眼点'）由医疗热词表与 LLM 纠错级联修正，全程本地引擎，数据不出院。」

### 2:30–5:00 AI 生成 + 四色确认（核心，放慢）

- 点「结束问诊，AI 生成」→ 六智能体**流式逐个亮灯**（信息抽取 → 数据汇聚 → 知识检索 → 病历生成 → 质控校验 → 字段映射）。
- **话术**：「六个角色各司其职，编排器按文书类型调度 DAG，每个字段携带来源与置信度。」
- 四色确认页（**汇报重点**）：
  - 🔵 **蓝 = HIS 带入**：「体温、检验、CT 印象来自院内 8 表导出，不是 AI 编的。」
  - 🟢 **绿 = 对话提炼**：点**溯源**按钮 → 弹出对话原文。「主诉'腹痛1天'对应录音里的'从昨天下午都开始痛'——**每个绿字段可回溯到原话**，这是医疗场景的信任基础。」
  - ⚪ **灰 = 规范所见**：「按临床常规合成，请医生过目。」
  - 🟡 **黄 = 缺失待补**：「对话没提到的，**宁可空着也不编造**——无录音时病史类字段硬拦截，这是安全底线。」
- 指 QC 报告条：「质控智能体自动标出疑似过度推断，生成与质控双防线。」
- 现场改 1 处字段 → 点「修改」→「改前改后自动留痕，稍后在修改回流里可见。」

### 5:00–6:30 归档 + 打印 + 审签 + 质控（快节奏）

- 「医生确认无误，提交归档」→ 出现**真实归档编号** AR-YYYYMMDD-NNNN。
- 「🖨 打印 / 存 PDF」→ 干净病历版式。
- 退出 → 登录**上级医师** → 「📋 审签待办」提醒卡 → 打开文书 → **签发**。
- 退出 → 登录**质控科** → 「🔍 抽查合格」→ 切「🛡 审计日志」：「登录、生成、归档、审签、抽查**只追加、不可篡改**。」

### 6:30–7:30 数据闭环收尾

- 质控科身份切「🔄 修改回流」：字段热点 × 四色来源。「绿字段被改得多 → 抽取提示词要优化；蓝字段被改得多 → HIS 映射要校准。**用得越多越准**，这是自我改进闭环。」
- 「⬇ 导出台账 CSV」：科室质控例会直接可用。

### 7:30–10:00 技术路线与数据（不操作，讲）

按第四节顺序讲：架构分层 → 自建 ASR 与实测数据 → 数据飞轮 → 评测体系 → 风险与边界。

### 10:00–12:00 下一步规划

0. **验证阶段收口与项目落地（当前主线，2026-10-24 更新）**：最简验证链路（上传方言转写稿 → 六智能体生成 → 导出 XML）已闭环并部署公网——qwen-max 实测 43 秒 32 字段（绿 5：主诉/现病史/既往史/个人史/婚育史，逐字段溯源），上传入口、预检工具、演示脚本与三层健壮性（SSL 重试/裸数组归一/截断自愈）全部就绪，预检六项全绿；院方演示时间待张老师确认，**技术侧零阻塞**，演示通过即进入报价环节。
1. **标注瓶颈攻坚**：门诊 5 段 25 分钟音频的 206 处分歧点，已做听力工作台（拆片/行内锚点）；标注完成后评测集从 1 例真实 → 6 例。
2. **方言模型路线**：数据到 50 小时门槛后立项 LoRA 微调；当前策略是"强中文基座 + 医疗域适配 + 方言纠错层"，不做孤立方言模型。
3. **两项目融合**：转录平台（通用产品形态）与病历系统（医疗大脑）合并为"基础设施 + 应用"两层，共享模型与热词资产。
4. **院内试点**：私有化交付包已就绪（Docker 离线部署 + 一键安装 + 验收自检），等院方服务器与密钥。

## 四、技术路线要点（导师最可能追问的地方）

### 4.1 系统本质：不是微调模型，是领域智能体系统

> 「本项目**没有训练任何模型**。所有模型（语音识别、大语言模型）都是现成能力，以可插拔方式接入；系统的价值在**机制、数据、评测**三样资产——四色确认与责任设计、语料库与热词表、回归基线与净 CER 口径。这三样换不走，模型随时可换。」

这个定位很重要：如果被问"你这是不是调了个 API"，如实回答"是，且这是刻意设计"——因为医疗系统的壁垒不在模型参数，在流程嵌入与责任边界。

### 4.2 语音识别：自建路线与实测数据

| 结论 | 数据 |
|---|---|
| 本地引擎已可零外呼运行 | FunASR（SenseVoice/SeACo）+ faster-whisper 接入引擎层，模型本地缓存后可完全断网；批量推理 RTF≈0.04 |
| 真实方言录音的难度 | 患者F 93.7s：whisper-small beam5 CER **66.5%**，加 LLM 方言纠错级联后 **56.9%**，事实保留 **12/12**、难点短语 7/7 |
| 最大单一增益是纠错级联 | 三引擎级联后事实保留全部 11/12→12/12；热词规则生长后 LLM 边际增益从 -9.6pp 降到 -3.2pp（确定性规则接管约 2/3） |
| 换更大模型不解决问题 | whisper-large-v3-turbo 患者F CER 79.4%（反比 small 差）、门诊仍幻觉——**数据才是瓶颈，不是模型规模** |
| 不做孤立方言模型 | 鲁西官话与普通话互通度高，错例是口音/吞字近音讹变，不是语系差异；正确命题是"强中文基座 + 医疗域适配 + 方言纠错层" |

### 4.3 数据飞轮（已落地，不是设想）

- `asr_corpus.py`：每接入一例，一条命令完成"引擎转写 → CER/事实对比 → 报告落盘 → 语料归集 → 门槛进度"。
- `asr_reconcile.py`：双引擎交叉只列分歧点，标注从"逐字听写 3500 字"变"仲裁 206 处"。
- `asr_annotate.py`：分歧点听辨工作台（拆片 / 行内锚点 / 自动成稿）。
- `hotword_harvest.py` + `hotword_audit.py`：热词表自动生长 + 全语料双向审计（发版关卡）。
- 当前语料：6 个真实案例（0.44 小时）；微调门槛 50 小时，**标注是唯一瓶颈**。

### 4.4 评测体系（有据可查）

- 无录音基线（36 份文书金标准反推）：录音依赖度 入院 54.1% / 出院 64.8% / 首程 66.8%——这是"必须补采录音"的量化依据。
- 首例真实案例（患者F）：无录音 26 字段绿 0 vs 真实录音 32 字段**绿 6**（病史类整体解锁）。
- 多智能体回归：首程准确率 23.0% → **59.2%**。
- 工程质量：**100 项单元测试 + 22 项 HTTP 冒烟 + 17 项仓库体检**（含患者真名零入库、密钥扫描、GitHub 同步状态）。

### 4.5 边界与风险（主动讲，比被问出来好）

| 风险 | 现状与对策 |
|---|---|
| 标注瓶颈 | 门诊 5 段待人工仲裁；已做听力工作台降低单例成本 |
| 方言准确率 | 当前最佳组合净 CER ~56%（真实方言、单例）；目标云端标尺 20~35%，需数据积累 |
| 角色分离缺失 | 本地引擎尚无医/患分离，后处理标注；cam++/3D-Speaker 为后续选项 |
| 单例样本不足 | 已评测仅 1 例真实 + 1 例合成回归；结论需多案例复选（门槛 5 例） |
| 交付/合规 | 私有化交付包已就绪；知情同意书"模型优化"条款待医务科确认 |

## 五、降级预案（任一故障不冷场）

| 故障 | 切换动作 | 话术 |
|---|---|---|
| 公网打不开 / 网络断 | 切手机热点；仍不行则开本地 `http://127.0.0.1:8765`（演示模式） | 「这是网络问题；架构与流程完全一致，本地是同一套前端」 |
| LLM 生成失败（503/超时） | 退出登录走演示模式：患者A 全流程用预置草稿 + 模拟归档 | 「正式环境是实时生成，这里降级为预置结果，确认流程不变」 |
| 账号登录异常 | 现场注册三角色（各约 30 秒） | 「顺便演示注册与角色体系」 |
| 录音页无麦克风 | 切"播放真实录音转写稿"路径（本来就是这个） | 「HTTP 页面浏览器禁用麦克风，所以用已采集的真实录音——效果一致」 |
| 被问倒 | 记录下来，会后书面回复 | 「这个问题我记下来，会后整理给你」 |
