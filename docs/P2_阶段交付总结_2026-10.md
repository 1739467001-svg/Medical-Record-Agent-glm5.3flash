## 二、量化评测基线（金标准反推法，PRD 7.1）

36 份真实文书 × DeepSeek 真实评测（`evaluation/reports/评测报告_multiagent_2026-10-01.md`）：

| 文书 | 覆盖率 | 准确率 | 录音依赖度 |
|---|---|---|---|
| 入院记录 ×12 | 14.1% → **15.4%** | 50.7% → **56.2%** | 54.1% |
| 出院记录 ×12 | 11.3%（首期） | 47.3% | 64.8% |
| 首次病程记录 ×12 | 6.5% → **11.5%** | 23.0% → **59.2%** | 66.8% |

**核心结论：录音依赖度 54%~67% 是三类文书的共同天花板**——无录音时覆盖率远低于 PRD 7.2 验收线（≥90%），录音补采是全项目第一优先级（量化依据即上表，可直接向院方说明）。

回归自动化：`python3 evaluation/run_regression.py` 一键完成三类文书评测 + 与上期按文书类型 diff，报告落盘 `evaluation/reports/`（md+json），双周回归（PRD 12.2-6）已从手动变一键。

## 六、录音数据到位后的接入 Runbook

1. **数据落位**：录音文件按患者/住院次命名放入约定目录（与 `病历资料/住院/` 金标准对应），随后执行 `python3 tools/asr_ingest.py 病历资料/录音 --validate` 自动校验格式与命名并生成落位报告
2. **引擎配置**：服务器 `.llm_env` 增 `ASR_DEFAULT_ENGINE=xfyun`（或商汤/阿里）+ 对应 `ASR_*` 密钥 → `docker compose restart llm-api` → 录音页自动切真实模式
3. **转写联调**（批量：`python3 tools/asr_ingest.py 病历资料/录音 --transcribe`，逐条走一遍）：真实录音走一遍 录音→转写→生成→确认（引擎角色分离能力以实际为准，过程稿支持人工标注修正）
4. **端到端评测**（模式 C 已实现并彩排验证：`MULTIAGENT_MODE=C` + `REHEARSAL_TRANSCRIPT`，彩排报告 docs/录音链路彩排报告.md；真实录音到位后重跑三类文书评测），形成"录音补采后"的完整基线——预期覆盖率大幅抬升（录音依赖度即理论上限）
5. **方言准确率评估**：用 ASR 测试集脚手架（`evaluation/asr_testset/`）对照标注规范评估方言识别质量
