### P2-H 规范用语改写 + 回归自动化 ✅ 已完成（2026-10-01，纯自研）
**背景**：首程评测暴露的最大自研短板——初步诊断（×11）/主诉（×10）"尝试未命中"。复现定位四个根因：
1. 诊断靠 LLM 自由归纳，产生幻觉改写（"慢性阑尾炎"被写成"急性单纯性阑尾炎"），而金标准即申请单诊断的规范表述；
2. HIS 视图为患者级导出，多次住院的申请单诊断/检查/医嘱混入本次住院（跨住院次张冠李戴）；
3. 无录音时 LLM 从诊断线索反推编造主诉（违反"材料未提及不产出"铁律）；
4. writer 只读前 6 条诊断线索（clinic_diags[:6] 截断）。

**改动（生成→质控→回流闭环）**：
- writer：诊断字段改为"申请单诊断规范改写"产出（规则直填兜底 `_rule_diagnosis` + LLM 筛选规范：保留病名原文/剔症状条目/合并重复/去"？"，不得从检查印象新增）；无对话素材时硬拦截主诉/现病史/既往史/个人史/婚育史/家族史/诊断依据（鉴别诊断/诊疗计划保留灰源知识辅助）；诊断线索送 LLM 前先归一化并放宽到 12 条
- aggregator：`from_patients_json` 将 demo 病例 `disease` 字段映射为 `clinic_diags`，服务端 Demo 路径诊断生成不回归
- common：`normalize_diag_text()` 规范用语归一（去"？"、去 ICD"其他的"尾缀），writer/QC 共用
- qc：诊断规范用语回流——逐条去"？"/ICD 尾缀后修正写回字段（只删不改），与 P2-C 诊断一致性校验构成质控双保险；修复 warnings 被复核层重置的问题
- 评测适配层（generate_multiagent）：住院次窗口过滤——按文书名日期（入院/首程 ±3 天、出院 ±14 天）只保留本次住院的 HIS 数据行，修复跨住院次混淆；窗口空表清空、无日期列联接表原样保留

**回归自动化（PRD 12.2-6）**：`evaluation/run_regression.py` 一键完成三类文书评测 → 报告落盘 `evaluation/reports/`（md+json）→ 与上期报告 diff（按文书类型对比覆盖率/准确率/录音依赖度 pp 变化 + 字段级命中/未命中变化）→ diff 结论写回新报告。支持 `--no-run`（只 diff）与历史 md 基线解析。

**验收（2026-10-01 全量回归实测，36 份文书，与 9-29/10-01 基线同模式对照）**：
- 首次病程记录：覆盖率 6.5%→**11.5%**（+5.0pp），准确率 23.0%→**59.2%**（+36.2pp）；初步诊断命中 ×1→×7，主诉 ×10 次虚假尝试全部消除（转黄=录音依赖），诊断依据 ×6 次编造尝试清零；"尝试未命中"64→22
- 入院记录：覆盖率 14.1%→**15.4%**，准确率 50.7%→**56.2%**；初步诊断命中 ×2→×7；收缩压/脉搏/舒张压命中 ×6/7/7→×11（住院次过滤顺带修正体征锚点错位）；"尝试未命中"196→173
- 出院记录（首期）：覆盖率 11.3%、准确率 47.3%、出院诊断命中 ×4
- 详见 `evaluation/reports/评测报告_multiagent_2026-10-01.md` 的"与上期回归对比"节

### P2-G 多角色与审签流 ✅ 已完成（1aee908，纯自研，提前实施）
**业务逻辑**（PRD 2.1 责任矩阵）：住院医师书写四色确认 → 提交归档（submitted）→ 上级医师审签（签发 signed / 退回 rejected，原因回流）→ 质控科抽查（合格 / 缺陷，独立标记）。归档从"演示模拟"升级为真库存储。

- **角色模型**：`users.role` ∈ resident（住院医师，默认）/ attending（上级医师）/ qc（质控科），注册页选择，`_public_user` 携带 role/role_name；老库自动迁移（MySQL information_schema / SQLite PRAGMA 判列后 ALTER）
- **归档存储**（server/records.py，与 auth 同连接层）：archives 表（归档编号 AR-YYYYMMDD-NNNN、四色字段包、QC 报告、修改留痕、XML 回填包、黄字段计数）；首启自动播种 2 条演示记录，上级医师/质控科登录即有可操作内容
- **API**（llm_api 挂载 /records/*，全部要求登录）：submit（提交归档）/ list（住院医师仅本人，上级/质控全量，status 筛选 + 统计）/ detail（权限校验）/ review（仅 attending，状态机防重复审签，退回原因必填）/ spotcheck（仅 qc）
- **前端**（app.js）：注册角色选择；顶栏角色徽章 + 「审签」导航（attending/qc 可见）；确认页提交真归档（登录用户，服务异常自动降级演示归档）；归档回执显示真实编号与审签状态；审签工作台（#/review，按角色三态视图：上级医师签发/退回、质控科抽查、住院医师本人进度与退回原因回流）
- **验收**：本地浏览器端到端（住院医师生成→确认→真归档 AR-20261001-0001 → 上级医师签发 → 质控科抽查合格）+ 生产公网实测（MySQL 角色列迁移、审签 API、种子数据）；角色越权 403、未登录 401、重复审签 409 如实拦截
