## 1. 交付形态总览

### 1.1 架构定位

系统以 **B/S（浏览器/服务器）** 形态交付，与院内其他信息系统（HIS/EMR/LIS）使用习惯一致：

- 医生在诊室/病房 **PC 浏览器** 中使用，无需安装任何客户端；
- 系统以 **Docker 容器** 运行在 **医院信息科机房的内网服务器** 上；
- 数据库（MySQL）、病历文书、录音文件全部落在院内，**不依赖任何公网云存储**；
- 对外仅有一个 HTTP/HTTPS 入口（经院内 nginx 反代），可纳入医院统一门户/导航页。

### 1.2 组件拓扑

```
医生 PC / 护士站 PC（Chrome / Edge 浏览器）
        │  http(s)://<院内地址>/mra/
        ▼
┌─ 院内服务器（信息科机房，Docker）─────────────────────┐
│                                                        │
│  ① medical-record-agent（nginx 静态容器）              │
│     端口 8080 → 医生端网页工作台（demo/ 静态站）        │
│     健康检查：GET /index.html → 200                    │
│                                                        │
│  ② mra-llm-api（Python API 容器）                      │
│     端口 8090 → 认证 / AI 生成 / 归档审签 / ASR 上传    │
│     健康检查：GET /health → 200                        │
│     内部以 MCP stdio 方式调用 asr_mcp_server.py        │
│                                                        │
│  ③ MySQL 8（可容器化或用院内现有实例）                  │
│     表：users / sessions / archives / audit_log        │
│     （启动自动建表，无需手工 DDL）                      │
│                                                        │
│  ④ 录音与转写文件（本地目录，随归档管理）               │
└────────────────────────────────────────────────────────┘
        │                              │
        │ 出口白名单（方案A，见 §6.2）  │ 全本地（方案B）
        ▼                              ▼
   LLM API（如 DeepSeek）        本地 LLM（vLLM 等，
   语音云 API（如讯飞）          兼容 OpenAI 接口）+
                                 本地 faster-whisper
```

### 1.3 与当前云端试运行的差异

| 维度 | 当前云端试运行（阿里云） | 私有化交付（目标形态） |
|---|---|---|
| 部署位置 | 公网云服务器 | 医院内网服务器 |
| 患者数据 | 仅脱敏演示数据 | 真实病历（含录音）落院内 |
| 访问方式 | `http://IP/mra/` | 院内域名/导航页入口 |
| 依赖公网 | 是（LLM/ASR 云 API） | 按方案 A 白名单外呼，或方案 B 全本地零外呼 |
| 适用场景 | 试点演示、联调 | 正式临床使用 |

## 2. 环境要求

### 2.1 服务器硬件（建议配置）

| 项 | 最低配置 | 建议配置（含本地 ASR/LLM 时） |
|---|---|---|
| CPU | 2 核 | 8 核+（本地 whisper/LLM 需 GPU 服务器另行评估） |
| 内存 | 4 GB | 16 GB+ |
| 磁盘 | 40 GB 系统盘 | 200 GB+（病历文书 + 录音归档 + 数据库 + 备份） |
| 操作系统 | Ubuntu Server 22.04/24.04（已验证）、麒麟 V10 等 Linux 发行版 | 同左 |

> 说明：核心两容器（静态 + API）资源占用很低（实测内存 < 100 MB 级，生产限幅 96m/64m）。磁盘容量主要由**录音文件**与**数据库**决定，按每床日录音 2 分钟（约 2 MB WAV）+ 文书与日志估算。

### 2.2 软件要求

| 软件 | 版本 | 说明 |
|---|---|---|
| Docker Engine | 20.10+ | 医院无外网时用离线包安装（§4.2） |
| Docker Compose | v2（`docker compose` 子命令） | 随 Docker 一并安装 |
| MySQL | 8.0 | 可复用院内现有实例，需建独立库与账号（§5.4） |
| nginx | 院内已有反代即可 | 静态站已由容器内 nginx 承担，宿主 nginx 仅做入口反代与 HTTPS |

### 2.3 网络要求

1. **入网方式**：服务器分配院内固定内网 IP；医生工作站所在网段可访问该 IP 的 80/443 端口。
2. **出口外呼**（仅方案 A 需要）：信息科防火墙放行两类白名单——
   - LLM API 域名（如 `api.deepseek.com`，HTTPS 443）；
   - 语音云 API 域名（如讯飞 RTASR `rtasr.xfyun.cn`，HTTPS/WSS）。
3. **零外呼**（方案 B）：不申请任何出口，LLM 与 ASR 全部本地部署（§6.3）。
4. **浏览器**：Chrome / Edge 最新版（录音与打印/存 PDF 功能依赖现代浏览器）。

### 2.4 浏览器录音的安全上下文硬约束（重要）

医生工作台的**问诊录音**功能使用浏览器 `MediaRecorder` 采集麦克风。浏览器安全策略规定：**只有 HTTPS 页面或 `localhost` 页面才能申请麦克风权限**。因此：

- 院内若以 `http://192.168.x.x/mra/` 直接访问，浏览器将**禁用麦克风**（录音页会给出降级提示）；
- 私有化交付必须二选一：
  - **推荐**：配置院内 DNS 别名（如 `mra.hospital.local`）+ HTTPS 证书（院内 CA 签发或自签证书导入信任），以 `https://mra.hospital.local/mra/` 访问；
  - 过渡期：医生端录音改用"录音笔/手机录好 → 文件上传"模式（上传通道不受此限制），文书生成不受影响。

## 3. 交付物清单

乙方按以下清单向信息科移交（示例目录名 `mra-delivery-v1.0/`）：

| # | 交付物 | 内容 | 说明 |
|---|---|---|---|
| 1 | `images/*.tar` | Docker 镜像离线包 | 预构建 `mra/llm-api:<版本>`（python:3.12-alpine 基座 + **ffmpeg**，支持 mp3/m4a 上传转码；`--with-local-asr` 时另含 faster-whisper）、`nginx:1.27-alpine`、可选 `mysql:8.0`（经 `docker save` 导出，院内 `docker load` 导入） |
| 2 | `docker-compose.yml` | 容器编排 | 私有化版（`deploy/offline/docker-compose.yml`）：端口/资源限幅变量化，MySQL 为可选 profile（`--profile mysql`） |
| 3 | `code/` | 全量代码包 | 仓库打包（或院内 Git 导入），含 `demo/`、`server/`、`mcp-server/`、`tools/` |
| 4 | `llm_env.template` | 密钥配置模板 | `.llm_env` 全量变量字典与填写说明（§5.3），**不含真实密钥**；install.sh 首次安装自动复制并引导填写 |
| 5 | `nginx/` | nginx 配置 | `static-default.conf`（静态容器内部配置）+ `mra-entry.conf.sample`（院内入口反代样例，含 HTTPS 段，§4.6） |
| 6 | `docs/` | 文档集 | 本说明书、《验收测试报告模板》（含人工验收项 checklist 与签字栏）、HIS 8 表接口字典、录音知情同意书模板、HIS 对接需求函 |
| 7 | `scripts/` | 运维脚本 | `backup-db.sh`（数据库备份，保留 14 份轮转）；版本更新走交付包整体替换（§8.3） |
| 8 | `models/`（仅方案 B） | 本地模型文件 | faster-whisper 模型目录，离线随包交付；`ASR_LOCAL_MODEL=/models/<名>` 生效 |
| 9 | 《验收测试报告》模板 | 验收清单执行结果（§7） | 自动项 `verify.sh --deployed` + 人工项 checklist，双方签字确认用 |

**整套交付包由仓库 `deploy/offline/make_delivery.sh` 一键生成**：代码经 rsync 红线排除（患者资料/真实录音/密钥/数据库文件零进入），产物再做二次红线扫描（音频/患者代号映射/疑似密钥零命中才放行）并生成全包 SHA256SUMS。包根目录另含 `install.sh`（院内一键安装，§4.0）、`verify.sh`（交付包自检 + 部署后自动化验收）、`VERSION`（记录代码 commit，可追溯）。打包选项：`--with-mysql` 附带容器化数据库镜像；`--with-local-asr` 镜像内置本地 ASR 依赖（方案B）。

> 代码与镜像不含任何患者数据（仓库红线：脱敏断言校验，`tools/check_repo.py` 可现场复验）。真实病历数据在部署验收后由院方经 HIS 接口/录音采集进入。

## 4. 安装部署步骤

以下命令均在院内服务器执行，默认部署目录 `/srv/apps/medical-record-agent/`（可自定义，后文以 `$APP_DIR` 指代）。

### 4.0 一键安装（推荐）

交付包根目录执行（幂等，重复运行安全；`--app-dir` 可自定义部署目录）：

```bash
sudo bash install.sh                 # 标准安装（对接院内已有 MySQL）
sudo bash install.sh --with-mysql    # 连数据库一并起（交付包容器化 MySQL）
```

脚本自动完成 §4.3–§4.7 的文件落位、离线镜像导入、`.llm_env` 生成（首次进入编辑器填写密钥）、compose 配置校验（占位符拦截）、启动与容器健康等待（最长 90s），最后打印验证结果。以下 §4.1–§4.7 为逐步展开，供排障与原理理解。

### 4.1 前置检查

```bash
# OS 与资源
uname -m && cat /etc/os-release && free -h && df -h /

# 网络与端口占用（确认 80/443 未被占用或已由院内 nginx 承担）
ss -tlnp | grep -E ':80|:443'
```

### 4.2 安装 Docker（无外网环境走离线包）

```bash
# 有外网（临时）
curl -fsSL https://get.docker.com | sh

# 无外网：乙方交付 docker-*.rpm/deb 离线包 + docker compose 插件离线包
# sudo dpkg -i docker-*.deb containerd-*.deb  && sudo systemctl enable --now docker
docker version && docker compose version   # 验证
```

### 4.3 落位文件与导入镜像

```bash
sudo mkdir -p $APP_DIR && cd $APP_DIR

# ① 代码落位（交付包 code/ → repo/）
sudo cp -r mra-delivery-v1.0/code ./repo

# ② 导入离线镜像
docker load -i mra-delivery-v1.0/images/nginx-1.27-alpine.tar
docker load -i mra-delivery-v1.0/images/python-3.12-alpine.tar
docker images   # 应看到两个镜像

# ③ 编排文件与反代配置
sudo cp mra-delivery-v1.0/docker-compose.yml .
sudo mkdir -p conf && sudo cp mra-delivery-v1.0/nginx/default.conf conf/
```

### 4.4 配置密钥与数据库

1. 按 §5.3 模板创建 `.llm_env`（LLM 密钥 / MySQL 连接 / ASR 引擎），`chmod 600`；
2. 按 §5.4 准备 MySQL 库与账号（复用院内实例或随包部署容器化 MySQL）。

### 4.5 启动

```bash
cd $APP_DIR
docker compose up -d                 # 对接院内已有 MySQL
docker compose --profile mysql up -d # 使用交付包容器化 MySQL（install.sh --with-mysql 同效）
docker compose ps                    # 两容器均应为 Up (healthy)
```

> 说明：`docker compose` 默认读取 `.env` 文件做变量插值（compose 里的端口/密钥/限幅变量）。install.sh 已自动建立 `.env → .llm_env` 软链，手工部署时需自建：`ln -s .llm_env .env`。占位符（`<>` 包裹的值）未填写时 `docker compose config` 会直接报错拦截，属预期防护。

### 4.6 入口反代与 HTTPS（信息科配合）

院内 nginx 增加反代片段（样例）：

```nginx
# /mra/ → 静态工作台（宿主端口按实际映射调整，示例 3904）
location /mra/ {
    proxy_pass http://127.0.0.1:3904/;
}
# /mra/api/ → API 容器（示例 3905）；/api/ 前缀由后端自动剥离
location /mra/api/ {
    proxy_pass http://127.0.0.1:3905/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    client_max_body_size 50m;   # 录音上传
}
```

如需 HTTPS（推荐，见 §2.4 麦克风约束）：按院内 CA 流程为 `mra.hospital.local` 签发证书，挂载至院内 nginx 并监听 443。

### 4.7 部署验证

```bash
bash verify.sh --deployed   # 自动化验收（容器健康/页面/API/权限/限流，结果可贴入验收报告）
# 或手工逐项：
docker inspect --format "{{.State.Health.Status}}" medical-record-agent   # healthy
docker inspect --format "{{.State.Health.Status}}" mra-llm-api            # healthy
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3904/index.html   # 200
curl -s http://127.0.0.1:3905/health                                      # {"ok":true,...}
```

浏览器访问 `http(s)://<院内地址>/mra/`：出工作台首页即部署成功；随后按 §7 验收清单逐项测试。

## 5. 配置说明

### 5.1 端口规划

| 容器 | 容器内端口 | 宿主映射（默认） | 公开范围 |
|---|---|---|---|
| medical-record-agent（静态） | 8080 | `127.0.0.1:3904` | 仅经院内 nginx `/mra/` 暴露 |
| mra-llm-api（API） | 8090 | `127.0.0.1:3905` | 仅经院内 nginx `/mra/api/` 暴露 |
| MySQL（如容器化） | 3306 | 建议不映射公网端口 | 仅容器网络内访问 |

> 宿主端口绑定 `127.0.0.1` 是刻意的：所有外部访问必须过院内 nginx 统一入口，便于信息科管控与审计。与其他院内系统端口冲突时，仅需改 compose 的宿主侧端口。

### 5.2 目录结构（部署后）

```
/srv/apps/medical-record-agent/
├── repo/                  # 代码（demo/ server/ mcp-server/ tools/ ...）
├── conf/default.conf      # 静态容器 nginx 配置
├── docker-compose.yml     # 编排
└── .llm_env               # 密钥与连接配置（chmod 600，不入备份外发）
```

### 5.3 `.llm_env` 配置字典（模板）

```bash
# ── LLM 生成服务（方案A：云端 API；方案B：本地 vLLM 地址）──
LLM_API_BASE=https://api.deepseek.com/v1     # 方案B 改为 http://<GPU服务器>:8000/v1
LLM_API_KEY=<密钥>                            # 方案B 用本地服务任意占位或专用key
LLM_MODEL=Deepseek-v4-flash                   # 方案B 改为本地模型名

# ── 数据库（MySQL；未配置时自动降级 SQLite，仅研发用，生产必须配置）──
MRA_MYSQL_HOST=host.docker.internal           # 容器访问宿主 MySQL；独立容器网络改为实例地址
MRA_MYSQL_PORT=3306
MRA_MYSQL_USER=mra
MRA_MYSQL_PASSWORD=<强密码>
MRA_MYSQL_DB=medical_record_agent

# ── 语音识别引擎（按选定方案启用，见 §6）──
ASR_DEFAULT_ENGINE=xfyun                      # xfyun / aliyun / sensetime / local-whisper / mock
# 讯飞 RTASR：
ASR_XFYUN_APP_ID=<appid>
ASR_XFYUN_API_KEY=<apikey>
ASR_XFYUN_HOTWORDS=<热词表，逗号分隔，医疗术语/科室/药品名>
# 本地 faster-whisper（方案B / 无外呼）：
ASR_LOCAL_MODEL=base                          # base/medium 或模型目录路径
ASR_LOCAL_PROMPT=<领域提示，建议带科室常见诊断>
```

> 权限与安全：`chmod 600 .llm_env`；该文件**永不入 Git、永不随备份外发**。其余可选变量（限流、端口、数据路径）见 `server/llm_api.py` 头部注释与 `mcp-server/README.md`。

### 5.4 MySQL 准备（一次性）

```sql
CREATE DATABASE IF NOT EXISTS medical_record_agent DEFAULT CHARSET utf8mb4;
CREATE USER IF NOT EXISTS 'mra'@'%' IDENTIFIED WITH mysql_native_password BY '<强密码>';
GRANT ALL PRIVILEGES ON medical_record_agent.* TO 'mra'@'%';
FLUSH PRIVILEGES;
```

- users / sessions / archives / audit_log 表由 `server/auth.py`、`server/records.py` **启动时自动建表**，无需手工 DDL；
- 容器访问宿主 MySQL 需在 compose 中保留 `extra_hosts: ["host.docker.internal:host-gateway"]`；
- MySQL 8 默认认证插件需 C 依赖，故按上方 `mysql_native_password` 建账号。

## 6. 网络方案选择（实施前与信息科确认的关键决策）

私有化部署唯一的对外依赖是 **LLM 生成服务** 与 **语音识别服务**。三个方案按合规强度递进：

### 6.1 方案对比

| | 方案 A：出口白名单 + 云端 API | 方案 B：全本地零外呼 |
|---|---|---|
| 形态 | 防火墙放行 LLM/ASR 云 API 域名 | LLM 用 vLLM 等本地推理（OpenAI 兼容接口）；ASR 用本地 faster-whisper |
| 患者数据流向 | **病历文本/录音会出院**（经 HTTPS 直达 API 服务商，厂商侧不留存需合同约定） | 完全不出院 |
| 识别/生成质量 | 最优（云端大模型 + 讯飞方言热词） | 中等（开源模型 + whisper，方言准确率下降，需本地评测） |
| 硬件成本 | 无新增 | 需 GPU 服务器（或接受 CPU 推理的时延） |
| 等保测评 | 需在数据出境/委托处理条款中说明 | 最简（物理隔离） |
| 适用 | 试点期快速上线 | 正式运行期/信息科要求严格时 |

### 6.2 方案 A 实施要点

1. 信息科防火墙配置**域名级白名单**（仅放行 `LLM_API_BASE` 与讯飞域名，不开通用出网）；
2. 与 API 服务商签署数据保密/不留存条款，纳入院方合规档案；
3. 上线前在 `evaluation/asr_testset/`（真实方言录音测试集）上跑通引擎连通性与 CER 指标。

### 6.3 方案 B 实施要点

1. **本地 LLM**：GPU 服务器部署 vLLM（或 Ollama）承载开源模型，暴露 OpenAI 兼容 `/v1/chat/completions`；`.llm_env` 的 `LLM_API_BASE` 指向该地址即可，**业务代码零改动**；
2. **本地 ASR**：faster-whisper 模型随交付包离线带入；`ASR_DEFAULT_ENGINE=local-whisper`；
3. 用 `evaluation/run_regression.py` 在本地模型上重跑三类文书基线，与云端基线对比，向院方出具差异说明。

> 建议路径：试点期方案 A（质量优先）→ 并行开展本地模型评测 → 按信息科要求切换方案 B。两方案对系统是纯配置差异，切换不动代码。

## 8. 日常运维（移交信息科）

### 8.1 监控与日志

```bash
docker logs --tail 100 medical-record-agent     # 静态站访问日志
docker logs -f mra-llm-api                      # API 运行日志（认证/生成/ASR/审计写入）
docker inspect --format "{{.State.Health.Status}}" mra-llm-api   # 健康状态
```

- 日志驱动为 json-file 且限幅（1m×3），不会撑爆磁盘；
- 业务留痕：登录/生成/归档/审签/抽查/转写均只追加写入 `audit_log` 表，质控科可在审签工作台「🛡 审计日志」页签直接查阅。

### 8.2 备份与恢复

```bash
# 数据库逻辑备份（保留最近 14 份；建议 crontab 每日 02:00）
bash $APP_DIR/repo/deploy/backup-db.sh
# crontab 示例：
# 0 2 * * * /srv/apps/medical-record-agent/repo/deploy/backup-db.sh >> /root/backup-db.log 2>&1

# 配置备份（compose + nginx 配置）
tar czf /root/backup-mra-conf-$(date +%F).tgz \
  $APP_DIR/{docker-compose.yml,conf,.llm_env} /etc/nginx/...

# 恢复：新建库后 gunzip < 备份.sql.gz | mysql -u mra -p medical_record_agent
```

> 录音与转写文件目录建议同步纳入医院现有备份策略（或按院方归档制度转存）。

### 8.3 版本更新与回滚

```bash
# 更新（乙方发新版本包 → 覆盖 repo/ → 重启 API 容器）
cd $APP_DIR/repo && <按版本包说明更新> && cd ..
docker compose restart mra-llm-api            # 静态卷挂载改动即时生效

# 回滚到指定版本
cd $APP_DIR/repo && git fetch --depth 20 && git checkout <commit> && cd .. && docker compose restart
```

### 8.4 密钥轮换

`.llm_env` 中各密钥到期/泄露时：改文件 → `docker compose restart mra-llm-api`，无需重建容器。

## 10. 常见问题（FAQ）

**Q1：医生电脑打不开录音功能/麦克风不可用？**
页面非 HTTPS（安全上下文）时浏览器禁用麦克风。按 §2.4 配置院内 DNS + HTTPS；过渡期用录音文件上传通道。

**Q2：系统提示 LLM 未配置/降级？**
`.llm_env` 缺 `LLM_API_BASE`/`LLM_API_KEY`，或方案 A 下防火墙未放行 API 域名。验证：`curl -s http://127.0.0.1:3905/health` 查看 LLM 配置状态。

**Q3：讯飞转写报错/无结果？**
依次检查：`ASR_XFYUN_APP_ID/API_KEY` 是否正确 → 防火墙是否放行 `rtasr.xfyun.cn` → `docker logs mra-llm-api` 中 ASR 错误详情；`api/asr/status` 可探测引擎就绪状态。

**Q4：能不用 Docker 直接装吗？**
可以但不在标准交付范围：静态站任意 HTTP 服务托管 `demo/`，API 用 `python3 server/llm_api.py` 起进程（systemd 托管）。Docker 方式具备资源限幅、健康检查、版本一致性保障，为推荐形态。

**Q5：想换一家 LLM/语音厂商？**
均为配置级切换：LLM 只要兼容 OpenAI `/chat/completions` 接口改 `LLM_API_BASE/MODEL` 即可；ASR 引擎在 `mcp-server/asr_mcp_server.py` 的适配器契约下可插拔（讯飞/阿里云/商汤/本地 whisper 已留适配位）。

**Q6：和 HIS/EMR 怎么对接？**
按 `docs/HIS数据接口说明_8表字典_v1.0.md`（8 表只读视图）与 `docs/对院方推进/02_HIS对接需求函` 推进；阶段一先以导出表接入，阶段二谈实时接口与病历回写。

**Q7：服务器重启后系统会自动起来吗？**
会。两容器均 `restart: unless-stopped`，MySQL/院内 nginx 按院方现有高可用策略。
