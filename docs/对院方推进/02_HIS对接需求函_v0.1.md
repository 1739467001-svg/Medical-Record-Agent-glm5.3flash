## 一、背景

AI 病历智能体系统已完成研发验证：以医生与患者的住院对话为入口，经语音转写与多智能体处理，按院内 XML 病历模板（XTextDocument）生成病历草稿，经医生四色确认、上级医师审签后形成归档包。**系统当前已具备按院内模板产出填充完成的病历文书（XML）与结构化归档包的能力**，申请启动 P3 阶段的 HIS/EMR 对接，实现归档回写。

## 二、回写方案：两步走（第一步不依赖写接口，可立即实施）

| 步骤 | 方式 | 前提 | 效果 |
|---|---|---|---|
| **第一步 · 导出+院内导入（兜底）** | 系统导出「归档包」（XML 填充文书 + 结构化 JSON，格式见附二），通过院内已有导入通道或人工导入 EMR | 无需 EMR 提供写接口 | 全链路立即闭环，验证数据正确性 |
| **第二步 · 接口直写** | 若 EMR/编辑器提供写入接口，系统调用接口直接回写归档 | 需本函第三节资料到位 | 自动化归档，消除人工环节 |

两步可并行准备：第一步先行试用，第二步资料齐备后切换，切换不影响病历数据。

## 三、请信息科/厂商提供的资料清单（按优先级）

| # | 资料项 | 具体内容 | 用途 |
|---|---|---|---|
| 1 | **XTextDocument 编辑器信息** | 厂商、产品版本、模板文件（.xtd 等）样例、二次开发能力说明（是否提供写入 API/SDK、接口形式） | 确认第二步直写可行性与实现方式 |
| 2 | **EMR 病历文书入库接口（若有）** | 接口形式（WebService/REST/中间库视图）、鉴权方式、报文样例、字段说明 | 第二步直写开发 |
| 3 | **相关数据字典** | 科室、医护、患者 ID 的编码规则与对照表；病历类型编码 | 归档包字段对准 |
| 4 | **测试环境** | EMR 测试环境地址/账号、联调窗口与流程（是否需入院内驻场） | 联调不碰生产数据 |
| 5 | **归档合规要求** | 医生签名/CA 电子签章在回写中的要求；归档后修改补录的院内流程 | 回写数据满足病案合规 |
| 6 | **对接人** | 信息科开发对接人 1 名 + 业务对接人 1 名；预期联调时间 | 建立沟通通道 |

## 四、我方已就绪的内容

1. **归档包导出接口**：系统内每份经审签的病历可导出标准归档包（版本号 `mra-archive-v1`，含归档元数据、审签与抽查记录、四色字段包、机器质控报告、医生修改留痕、XML 回填文书），格式说明见附二；字段扩展随院方确认即时生效。
2. **字段地图 v0**：已从院内 75 份真实文书样例自动提取 239 个字段标签（含 111 个受控下拉字段），生成《字段地图 v0 确认表》（另附 Excel），请贵科组织病案/临床确认「哪些字段由 AI 填写」与下拉选项值——这是填充正确性的关键输入。
3. **安全与合规**：私有化部署数据不出院；全程操作留痕（审计日志）；AI 仅生成草稿，责任主体为医生；真实录音采集配套知情同意书（另附）。

## 附二 · 归档包格式说明（mra-archive-v1）

- **获取方式**：`GET /records/export?id=<归档ID>`（登录态，权限：上级医师/质控科全量、住院医师本人），返回 JSON 附件下载，文件名 `<归档编号>.json`。
- **包结构**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `format` | string | 固定 `mra-archive-v1`，对接方按版本解析 |
| `record_no` | string | 归档编号，`AR-YYYYMMDD-NNNN`（全院唯一） |
| `patient_code` / `admission_idx` | string / int | 患者编号与住院次 |
| `doc_type` / `disease` | string | 文书类型（入院记录/首次病程记录/出院记录…）与病种 |
| `resident_name` | string | 书写医生 |
| `status` / `created_at` | string | 审签状态（submitted/signed/rejected）与提交时间 |
| `signed_name` / `signed_at` / `sign_comment` | string | 上级医师签章信息与签发/退回意见 |
| `spot_result` / `spot_name` / `spot_comment` | string | 质控科抽查结果与意见 |
| `total_cnt` / `yellow_cnt` | int | 字段总数与缺失待补（黄）数 |
| `fields[]` | array | 四色字段包：`{label, value, source(blue/green/gray/yellow), binding…}` |
| `qc` | object | 机器质控报告：summary / blocked / missing / warnings |
| `edits[]` | array | 医生修改留痕：`{field, before, after, time, doctor}` |
| `xml` | string | **按院内 XTextDocument 模板填充的 XML 文书文本**（第一步导入的直接载体；如导出为空表示该类型暂未启用 XML 填充） |
