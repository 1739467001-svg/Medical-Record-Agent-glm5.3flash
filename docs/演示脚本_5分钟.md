> 适用：向院领导/医务科/信息科做首次演示或复演示。
> 原则：**每个环节都有降级预案**（见第四节），任何环境故障都能切换到不依赖外部服务的路径，演示不中断。

## 二、演示动线（约 5 分钟，按点击顺序）

### 0:00–0:30 开场定位（不操作系统，只说三句话）
1. 「医生负责看病，系统负责把看病的过程变成规范的病历草稿——**AI 只出草稿，医生确认后才归档，责任主体始终是医生**。」
2. 「演示数据来自院方真实病历脱敏再构（患者A/患者B）；**患者F 是贵院录音设备采集的首例真实案例**——真实方言问诊录音，本地转写、脱敏后接入，全流程真实运行，不含任何可识别患者信息。」
3. 「接下来 5 分钟走一条完整链路：问诊 → AI 生成 → 医生确认 → 归档 → 审签 → 质控。」

### 0:30–1:30 工作台与问诊入口（登录 demo_res）
- 登录 → 工作台：指出「今日书写任务」的**法定时限标注**（入院记录 24h、首程 8h）与待办统计；**患者F 任务卡带绿色「真实录音」标签**。
- 点患者F「进入问诊流程」→ 录音页。页面上有**两个入口**，按张老师 10.20 对齐会的定调，**首选动线是上传**：
  - **「📎 上传转写文本 / 音频」（主推）**：点按钮 → 选文件（院方已录好的 .wav/.mp3/.m4a，或已解析的 .txt/.md 转写稿）→ 转写区直接呈现解析结果，标题带「📎 上传：文件名」来源标注。话术：「电脑没有麦克风、环境嘈杂都没关系——**医生用现有设备录完，把文件传给系统就行**；文本直接进流程，音频走同一套转写引擎。」演示用 `病历资料/彩排录音/patient01_转写稿_纠错后.txt`（git 忽略区，真实转写稿纠错后净版）。
  - 「● 开始录音」（备选）：回放真实问诊录音的转写稿（50 轮，山东方言口音，页面标注"真实录音转写"），话术：「这段对话来自贵院采集的真实录音——方言口音由本地模型转写，'消炎针'这类方言同音错字由医疗热词表自动修正，数据全程不出院。」
  - 已配 ASR 密钥 → 也可现场真人录音实时转写；
  - 降级 → 患者A 演示对话仍保留（明确标注"演示回放"）。

### 1:30–2:30 AI 生成 + 四色确认（核心 3 分钟）
- 点「结束问诊，AI 生成」→ 六智能体**流式逐个亮灯**（抽取→汇聚→检索→生成→质控→映射），话术：「每个智能体各司其职，生成约十几秒。」
- 四色确认页（**演示重心，放慢**）：
  - 🔵 蓝=HIS 带入（指体温/脉搏/初步诊断/辅助检查）：「系统自动从院内数据带入——患者F 的异常检验、CT 印象都来自贵院 HIS 真实导出」；
  - 🟢 绿=对话提炼（点**溯源**按钮，弹出对话原文对照）：「主诉'腹痛1天'就是录音里患者说的'从昨天下午都开始痛'——每个绿字段可溯源到问诊原话，不是 AI 猜的」；
  - ⚪ 灰=规范所见：「按临床常规合成，请医生过目」；
  - 🟡 黄=缺失待补：「对话里没提到的，系统**宁可空着也不编造**——这是医疗安全底线」；
  - 指 QC 质控报告条：「质控智能体自动标出疑似过度推断的表述提请医生复核——生成和质控双防线。」
- 现场改 1 处字段（如主诉措辞），点「修改」：「每处修改自动留痕改前改后，稍后在修改回流里能看到。」

### 2:30–3:30 提交归档 + 打印
- 点「医生确认无误，提交归档」→ 归档回执出现**真实归档编号**（AR-YYYYMMDD-NNNN）：「进入院内审签流，不是模拟。」
- 点「🖨 打印 / 存 PDF」→ 弹出干净病历版式：「医生日常要的纸质/存档版式，浏览器另存为 PDF 即可。」

### 3:30–4:30 审签与质控（切换账号演示多角色）
- 退出 → 登录 demo_att：工作台顶部**「📋 审签待办」提醒卡**（刚提交的 1 份）→ 进审签工作台 → 打开文书 → 逐字段核查 → **✓ 签发**（填意见「同意签发」）。
- 退出 → 登录 demo_qc：审签工作台 → **🔍 抽查合格** → 切「🛡 审计日志」页签：「登录、生成、归档、审签、抽查**全程留痕、只追加不可篡改**，这就是医务合规要的审计线。」

### 4:30–5:00 数据闭环收尾
- 仍以质控科身份切「🔄 修改回流」页签：字段热点 × 四色来源（绿=对话提炼被改多→抽取提示词待优化）：「医生用得越多，数据越准——这是系统的自我改进闭环。」
- 回列表页点「⬇ 导出台账 CSV」：「科室质控例会和病案统计直接用 Excel 打开。」
- 结束语：「**首例真实录音案例（患者F）已经跑通全链路**——录音到位一批，传送带接入一批（每例约 10 分钟）；覆盖率将从无录音基线持续抬升，这是接下来的主要工作。」

## 三、可引用的量化结论（评委追问时用）
- **最新实测（2026-10-24，公网 qwen-max）：上传方言转写稿 → 43 秒生成 32 字段（蓝 8 / 绿 5 / 灰 19），主诉、现病史、既往史、个人史、婚育史由对话真实提炼，每字段带溯源依据；全程无降级。**这是"当前引擎、当前动线"下的现场可复现数据。
- 无录音基线（金标准反推评测，36 份文书）：入院记录对医患对话录音的**依赖度 54.1%**——不补录音，覆盖率上限约 46%，这是录音补采的量化依据。
- **首例真实录音案例实测（患者F，2026-10-09）**：无录音 26 字段（绿 0，病史类硬拦截）vs 真实录音 32 字段（**绿 6**：主诉/现病史/既往史/个人史/婚育史/家族史整体解锁），主诉与录音原话完全一致；质控复核提示全部命中 LLM 过度推断点。
- 多智能体实测（2026-10-01 回归）：首次病程记录准确率 23.0%→**59.2%**；初步诊断命中 ×1→×7；虚假"尝试未命中"大幅消除。
- 质量保障：**132 项单元测试 + 22 项 HTTP 冒烟测试**，一条命令回归（`python3 tools/check_repo.py`，18 项体检，含患者真名零入库扫描、上传解析 JS 回归、LLM 协议适配回归）。

## 五、常见提问 Q&A
- **数据安全？** 病历资料/录音/会议材料永久排除在代码库外；研发态云端调用仅送脱敏医学数据；LLM/ASR 密钥只存服务器 `.llm_env`（chmod 600）；正式部署私有化，数据不出院。
- **方言听不准？** 转写稿医生可改后再生成；录音留痕可回放；ASR 引擎可插拔可替换。
- **AI 写错了算谁的？** AI 只出草稿，四色确认前不进系统；确认后的修改全部留痕；责任主体始终是医生（PRD 2.1 责任矩阵）。
- **什么时候能接 HIS？** 归档 XML 回填包格式已按院内模板规范产出（XTextDocument/XML），等院方接口文档即启动对接（P2-F，已完成前置字段地图 v0）。
