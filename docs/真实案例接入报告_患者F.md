# 首例真实录音案例接入报告（患者F）

- 日期：2026-10-09　|　数据：院方录音设备采集的第 1 个真实案例（真实问诊录音 + HIS 8 表导出）
- 链路：真实录音 → 本地转写（faster-whisper small，数据不出机）→ 案例接入传送带（`tools/case_ingest.py`）→ 平台演示数据（脱敏）→ 六智能体生成（模式A/C 对照）→ 质控 → 四色确认
- 数据安全：原始数据（真实姓名/住院号/录音/转写稿）仅存于 git 忽略目录 `病历资料/住院/<姓名>/`；本报告与入库的演示数据均经红线扫描（真实姓名/住院号/手机号/证件号 0 命中方可落盘）；患者以代号 F 指代，医护以"姓+医生/护士"指代。

## 一、案例概况（脱敏）

| 项 | 内容 |
|---|---|
| 患者 | 患者F，男，28 岁，普通外科 |
| 住院 | 2026-10-02 入院 → 当日腹腔镜阑尾切除术 → 2026-10-08 出院（7 天） |
| 诊断 | 阑尾炎（申请单）；术后病理：急性坏疽性阑尾炎 |

录音双声道分析：声道相关系数 0.46、双声道全程均有能量——为**同室双麦拾音而非医患分轨**，不能靠声道免费获得说话人分离；角色区分走后处理（本例用 LLM 角色标注）。

## 二、方言 ASR 实测与引擎升级（规律沉淀 #1）

三轮 A/B 实测（同一段真实方言录音，faster-whisper small）得到的可复用结论，已固化进 `mcp-server/asr_mcp_server.py`：

1. **无领域提示时出现重复循环幻觉**（同句×7）与首尾幻觉（"七十年前"/"字幕by…"）——修复：`condition_on_previous_text=False` + 短领域提示。
2. **短主题式提示（~45字）显著优于长词表提示（>100字）**：短提示下"消炎针"直接识别正确、标点完整；长词表反而诱发幻觉。引擎默认提示已改为短主题式，可用 `ASR_LOCAL_PROMPT` 按案例覆盖。
3. **按案例定制提示最优**：把申请单诊断（如"阑尾炎"）写进提示，识别质量最佳——`case_ingest` 场景下可由 HIS 数据自动构造。
4. **方言同音错字成"变体族"**：一个方言词（消炎针）在不同轮次被误识为 小院人/小阳人/小眼人/小眼帘/小眼脸/小眼点 6 种变体——热词表按族补全（本次 +8 条规则）；每次修正在转写 warnings 留痕，医生确认兜底。
5. 转写终稿：热词修正 5 处（消炎针×4、体格×2 中命中的部分）；残留口语讹变（如"观点有""手势力"）交由抽取智能体做方言语义转写，不再靠热词硬修——**热词只修无歧义同音错字**的边界经实测有效。

## 三、案例接入传送带（迎接第 2、3 个案例）

新增 `tools/case_ingest.py`：一例真实数据（HIS 8 表 xls + 录音转写稿）→ 一条命令变成平台可用的脱敏演示数据。

```bash
# ① 录音落位转写（已有工具，命名约定 患者编号_入院日8位_文书类型.wav）
python3 tools/asr_ingest.py 病历资料/住院/<姓名>/录音 --validate
ASR_LOCAL_MODEL=small python3 tools/asr_ingest.py 病历资料/住院/<姓名>/录音 --transcribe --engine local-whisper

# ② 案例接入（自动探测入院/出院/科室/诊断；LLM 角色标注对话；红线扫描后落盘）
python3 tools/case_ingest.py 病历资料/住院/<姓名> --code DA00NN [--dry-run]
```

传送带做了六件事：
1. **强制 git 忽略校验**（与 asr_ingest 同规则），真实数据永不入库；
2. **HIS 8 表全量加载**（复用评测层 loader）+ 住院窗口过滤（±3 天，复用 P2-H 规则），多次住院历史数据不串案；
3. **自动探测案例事实**：入院/出院时间（生命体征/医嘱事件行）、科室（护理常规医嘱）、诊断（申请单 CLIN_DIAG）、性别/年龄（检验主表最近行）；
4. **模板骨架文书**：字段标签/绑定路径/受控标记复用模板患者（医院 EMR 模板与具体患者无关），值一律清空=黄色待生成；Patient 绑定字段按值形态回填脱敏登记信息（姓名→代号、住院号→掩码）；
5. **转写稿 → 角色标注对话**：LLM 判定医生/患者轮次 + 混说段落拆分 + mapsTo 溯源标注（启发式降级可用）；文本逐字保留（含 ASR 错字）——绿字段可溯源到医生实际说出的话；
6. **红线扫描**：从 8 表收集全部真实姓名/住院号（含医护姓名列 23 个），对输出 JSON 逐 token 扫描，任一命中拒绝落盘。

产出：`demo/data/patients.json` 追加患者条目（his 节 + 骨架文书）、`demo/data/dialogue_<code>.json`（真实对话）、案例目录内 `接入报告.md`（含真实值，git 忽略区，供人工核对）。

## 四、平台化改造（前端解除单患者硬编码）

演示前端此前的交互流程硬编码于患者A（36 处），本次改为数据驱动：

- 住院次带 `interactive` 标记即可进入完整流程（录音→生成→四色确认→归档），`real_recording` 标记显示"真实录音案例"徽标；**新案例接入 = case_ingest 落数据，前端零改动**；
- 对话按患者加载（`dialogue` 字段指向对话文件，缺省用演示对话）；工作台任务卡、患者卡片、打印/导出/修改留痕/归档回调全部按当前流程 key 动态解析；
- 顺带修复 GUI 实测发现的 3 个存量缺陷：溯源弹层 JSON.parse 崩溃、任务卡"草稿已生成"状态失真（未开始不再谎称已生成）、录音计时器不做分钟进位；50 轮长对话回放自动提速。

评测层同步升级：`load_his_views` 从 5 表扩至 **8 表**（医嘱/检验结果/检验申请项目此前被白白丢弃），`from_his_views` 聚合器本就消费医嘱与异常检验——本次接通后，异常检验进入"辅助检查"素材、医嘱进入"诊疗计划"素材；住院窗口过滤补充 `START_DATE_TIME/RESULT_DATE_TIME` 等日期列，历史住院次数据不泄漏进本次文书。

## 五、生成实测（模式A 无录音 vs 模式C 真实录音）

同一案例、同一平台链路（HTTP `/generate-draft`，六智能体真实运行，DeepSeek 驱动）：

| 指标 | 模式A（无录音） | 模式C（真实录音转写稿） |
|---|---|---|
| 产出字段 | 26（蓝7/绿0/灰19） | 32（蓝7/**绿6**/灰19） |
| 绿字段（对话提炼） | 0——无录音铁律生效，病史类字段硬拦截 | **主诉、现病史、既往史、个人史、婚育史、家族史** |
| 抽取智能体 | 跳过（无素材） | 50 轮对话 → 14 项医学要素（带轮次出处） |
| 汇聚智能体 | 4 检查/23 异常检验/60 医嘱/13 体征 | 同左（8 表全量接入后首次达到此规模） |
| 质控 | 通过 26 | 通过 32 · 复核提示 3 |
| 耗时 | ~10s | 11.6s |

**主诉"腹痛1天"与录音完全一致**（"从昨天下午都开始痛"）；现病史叙事（起病时间/镇上消炎针治疗无缓解/呕吐2-3次/无发热）逐项可溯源到对话轮次。录音依赖度理论（PRD：三类文书 54%~67%）在首个真实案例上兑现：**没有录音就没有绿字段，有了录音病史类字段整体解锁**。

### 质控防线实测（规律沉淀 #2）

QC 智能体对本例 LLM 过度推断的拦截全部命中要害（医生确认页同步展示）：
- 既往史"有手术史"——实为医生宣布的**本次手术安排**被误抽（已通过 extractor 提示词第 5 条修复：诊疗安排≠既往史）；
- "无过敏史"与对话要素不符（过敏史未被明确问及，属推断）；
- 家族史"无家族史"表述不规范且对话未实际采集（extractor 提示词第 6 条同步收紧）；
- 现病史"疼痛持续无缓解"属过度推断（对话仅提及起病时间）。

结论：**"生成端收紧 + 质控端兜底"的双防线在真实数据上有效**；LLM 单点错误可被 QC 捕获并前呈医生。

## 六、发现的平台级问题（待后续案例验证/排期）

1. **时间穿越**：入院记录为术前文书，但住院窗口（±3 天）把术后病理纳入了素材，初步诊断直接产出术后病理诊断。真实书写场景应按"文书锚点时刻"截断数据（入院记录只用入院时刻前数据）。当前四色确认由医生裁定可兜底，P3 对接前应在汇聚层实现时间截断。
2. **说话人分离缺失**：本地引擎不带角色分离（本例靠 LLM 后处理标注，效果可用但非声学证据）；云端引擎（讯飞/阿里）角色分离能力待密钥到位后以真实录音联调（Runbook 第 3 步）。
3. **同名字段合并的配色计数差异**：生成统计（按流水线字段）与确认页色点计数（按模板行）在重复标签字段上可相差 ±1，属展示口径差异，已记录。

4. `case_ingest.py <案例目录> --code DA00NN --dry-run` 核对探测结果与角色标注 → 去掉 `--dry-run` 正式落盘；

案例积累后的规律出口：转写稿语料 → ASR 方言测试集（`evaluation/asr_testset/`）标注 → 方言字错率基线；医生修改留痕 → 字段热点×四色来源回流分析（F8）。
