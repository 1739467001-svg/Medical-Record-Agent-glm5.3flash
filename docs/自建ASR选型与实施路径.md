# 自建 ASR 选型与实施路径（不依赖外部 API · 山东方言医疗场景）

| 项 | 值 |
|---|---|
| 日期 | 2026-10-16（首版） |
| 背景 | 现有链路依赖云端 ASR（讯飞等，密钥未到位）；私有化交付需"数据不出院"；患者F 首例真实方言录音实测 CER 65.1%（whisper-small） |
| 目标 | ① 自建可离线运行的 ASR 服务（零外呼）② 面向山东方言+医疗术语持续增强 ③ 云端 API 仅作可选对照 |
| 结论摘要 | **自建可行且已落地**：FunASR（SenseVoice/SeACo）与 faster-whisper 两族本地引擎接入 MCP 引擎层，患者F 案例完成对比评测；**LLM 方言纠错级联是当前最大单一增益**（事实 11/12→12/12；最优组合 CER 56.9%、难点短语 7/7）；单例样本不足以下最终结论，按"案例攒到 30+ 再定选型/微调"推进 |

## 一、路径总览（四阶段）

| 阶段 | 内容 | 状态 |
|---|---|---|
| ① 自建推理服务（不训练，开源模型） | FunASR / faster-whisper 接入引擎层，零外呼可跑；用现有评测脚本选型 | **本版完成** |
| ② 数据飞轮 | 每个真实案例自动沉淀"音频 + 校读稿 + 热词修正 + LLM 纠错 diff"（case_ingest 传送带已有） | 持续 |
| ③ 方言适配（30~50 例后） | 上下文偏置（热词）优先 → LoRA 微调；用积累数据立项 | 待数据 |
| ④ 对外服务（可选） | 院内先跑稳，再评估多院共享；须先解决数据合规（他院患者录音过本服务器）与算力账单 | 待评估 |

**为什么不做"山东方言专用模型"**：东阿属鲁西官话区，与普通话互通度高，患者F 错例（消炎针→小眼点、体格→提个）属口音/吞字近音讹变，不是粤语/闽南语式体系差异。正确命题是"强中文基座 + 医疗域适配 + 方言纠错层"，而非独立方言模型；且**纠错层是模型无关资产**（热词族 + LLM 级联），比押注单一模型更耐久。

## 二、已落地实现（本版）

### 2.1 引擎层（mcp-server/asr_mcp_server.py）

| 引擎 | 说明 | 关键环境变量 |
|---|---|---|
| `funasr`（新增） | 默认 `iic/SenseVoiceSmall`；可切 SeACo-Paraformer（**医疗热词解码期偏置**）；VAD 分段 + 超长段能量切分；Paraformer 系带标点 | `ASR_FUNASR_MODEL/DEVICE/HOTWORD/CHUNK_S/PUNC/VAD` |
| `local-whisper`（增强） | 档位/设备/精度可配；新增 `ASR_LOCAL_BEAM`（缺省 5） | `ASR_LOCAL_MODEL/DEVICE/COMPUTE/BEAM` |

- 统一后处理管线（热词修正 → 可选 LLM 方言纠错）对全部引擎生效，新引擎到即享；Transcript 含 `text_raw` 双版本留痕，绿字段溯源红线不破。
- `tools/asr_ingest.py --engine funasr` 直接可用（引擎名透传）。
- **性能（本机 M 系 CPU，SenseVoice 档）**：批量提交后 RTF≈0.04——患者F 93.7s 音频 4s、彩排 122s 音频 21s（优化前逐段调用 65s/412s，**提速约 20 倍**）；模型常驻进程内复用，无每请求重载。

### 2.2 分段策略（患者F 实测教训，重要）

funasr 的 VAD 会把无长停顿的长对话并成**一段 55.9s**；而本族模型在 >15~20s 长段上**显著退化**（SeACo 直接丢内容、SenseVoice 压缩掉字——首轮实测只转出后 1/3）。修正：**VAD 切段 + 超长段按能量最低点二次切分**（±1.2s 窗口内取 100ms 窗 RMS 最低处，避免切断词中），缺省上限 SenseVoice 15s / Paraformer 系 10s；**相邻短段再合并**（合计 ≤上限 且间隔 ≤800ms）并**一次批量提交**（摊薄逐段调用开销，实测逐段调用 RTF>3；批量失败自动逐段降级）。最终患者F 出 8~10 段（vs whisper 50 段），均带 start/end 时间戳。

另一个集成坑（已修）：funasr 在 import 时向 **stdout** 打印版本号，会污染 MCP stdio 协议流（客户端把 "funasr version: 1.4.16." 当 JSON 响应读，链路直接断）——适配器已将 funasr 的导入与推理全程重定向 stdout→stderr，端到端协议纯净性实测 0 污染行。

### 2.3 评测口径升级（evaluation/asr_engine_bench.py）

- 新增**净CER**（双侧同去语气词）：患者F 实测教训——SenseVoice 如实转写语气词（字数近参照 1.5 倍），标准 CER 把"忠实"误判为"错误"，清理型转写天然占便宜；净口径使两类风格可比。
- 新增明细 JSON 落盘（`<报告>.json`，含各引擎全文/警告，案例目录 git 忽略）——复查不必重跑。

## 三、患者F 实测对比（真实方言问诊 93.7s，参照=人工校读理解稿 218 字）

| 引擎 | CER | 净CER | 转写字数 | 事实保留 | 分段 | 备注 |
|---|---|---|---|---|---|---|
| whisper-small beam=1 | 70.2% | 68.1% | 299 | 11/12 | 36 | 贪心 |
| whisper-small beam=5 | 66.5% | 65.7% | 292 | **12/12** | 50 | 缺省档 |
| **whisper beam=5 + LLM 纠错** | **56.9%** | **56.0%** | 290 | **12/12** | 50 | **本案例全场最优** |

| funasr SenseVoice + LLM 纠错 | 85.3% | 71.3% | 335 | **12/12** | 8 | 级联后 |
| funasr SeACo+热词 | 89.0% | 73.6% | 345 | 11/12 | 10 | 解码期热词偏置 |

**难点短语逐项对照（纠错后文本，硬证据——CER 对"理解稿"参照受风格影响大，此项更可靠）**：

| 难点（参照） | whisper beam5 | whisper+LLM | SenseVoice | SenseVoice+LLM | SeACo+热词 |
|---|---|---|---|---|---|
| 消炎针（医生问） | ✓ | ✓ | ✓ | ✓ | ✓（**热词偏置直接听对**） |
| 消炎针（患者答） | ✓ | ✓ | 讹变（小炎点/小点） | ✓ | 讹变→已补热词规则（小圆点） |
| 体格 | ✓ | ✓ | ✓ | ✓ | ✓×4（含 1 处**热词误伤**，见 §六） |
| 药物过敏 | ✗（有关） | **✓（LLM 修）** | ✗（有关） | ✓ | ✗（有关门） |
| 既往痛过 | ✗（通过×2） | **✓（LLM 修）** | ✗（通过×3） | ✓ | ✗（通过×3） |
| 时间（七点多） | ✗（聊点多） | **✓（LLM 修）** | ✗（两点多） | ✗（两点多） | ✗（两点多） |
| 手术 | ✓ | ✓ | ✓ | ✓ | ✓ |

**结论（单例口径）**：
1. **LLM 方言纠错级联是全场最大单一增益**：whisper 66.5%→56.9%（-9.6pp）、SenseVoice 88.1%→85.3%、SeACo 89.0%→87.2%；三个引擎级联后事实保留全部 11/12→**12/12**，且把"过敏/痛过"两处系统性讹变修对，whisper 档连时间词（聊点多→七点多）都修对——**难点短语 7/7 全对**。
2. **本案例最优组合：whisper-small（beam=5）+ LLM 纠错级联**（CER 56.9%、事实 12/12、短语全对），且它就是现有引擎 + 已实现级联的直连组合，无需新增依赖。
3. **funasr 忠实转写风格在"理解稿"参照下天然吃亏**：CER 差距（~21pp）主要来自"语气词/重复/自我更正全保留"（净CER 已收窄到 ~8pp）；其不可替代价值在 **SeACo 热词解码期偏置**（术语级听音正确，whisper/SenseVoice 靠事后热词表兜底）与**不依赖 ctranslate2 的技术栈备份**（多一条自建路线）。
4. 单例样本、参照为理解稿（含自身误差），**不足以定终选**；下步按案例累计复测（见 §五）。

## 四、选型建议（当前）

- **推荐生产组合（本案例最优）**：`local-whisper`（beam=5）+ 热词后处理 + **LLM 纠错级联默认开**——CER 56.9%、事实 12/12、难点短语全对，全部为现有能力直连，零新增依赖。
- **并列一等候选**：`funasr`（SenseVoice）+ 热词 + LLM 级联——事实同为 12/12，忠实转写保留原始口语（下游可再清洗），技术栈不依赖 ctranslate2（多一条自建路线）；**SeACo 档**（热词解码期偏置）作为"术语密集科室"可选。
- **默认引擎切换**：`ASR_DEFAULT_ENGINE=funasr`（或 `local-whisper`），上层与后处理管线零改动；云端密钥到位后 `asr_compare` 一键三方同题复测（云端目标 CER 20~35%，作为自建差距标尺）。
- **热词表继续生长**（本版新增：小圆人/小圆点→消炎针、体个→体格、恶信→恶心；累计 25 条）；**LLM 纠错对照表**同步扩充（聊点多=七点多 等已生效）。

## 六、数据飞轮（第②阶段，已落地）

**工具**：`tools/asr_corpus.py`——每接入一例，一条命令完成"引擎转写 →（有参照稿则）CER/事实对比 → 报告落盘 → 语料库索引归集 → 门槛进度"；无参照稿的音频自动落**引擎草稿**（带时间戳，供人工标注）。语料库落 git 忽略区（`病历资料/ASR语料库/`），索引仅存路径与指标，不复制音频。

```bash
python3 tools/asr_corpus.py --add 病历资料/住院/<姓名> --whisper-model small --llm-polish  # 有参照：完整评测
python3 tools/asr_corpus.py --add 病历资料/门诊/1.m4a --llm-polish                        # 无参照：草稿待标注
python3 tools/asr_corpus.py --list    # 案例清单
python3 tools/asr_corpus.py --stats   # 累计统计与门槛进度
```

**标注加速器**：`tools/asr_reconcile.py`——两个独立引擎同题转写 → 字符级对齐（**去语气词口径**：whisper 丢语气词、SenseVoice 全保留，不去则一致率被伪分歧压到 40% 级）→ 只列**分歧点**听辨清单（带时间戳、上下文标记）：人工标注从"逐字听写"变成"分歧仲裁"，一致处直接采信；一致率 <60% 时明确警示"该音频需整段精听"。产物落 `病历资料/ASR语料库/校订稿/`。

- **引擎对选择有讲究（门诊实测）**：门诊嘈杂音频上 whisper-small 崩溃（幻觉+同句循环+繁体输出，无提示词也复现），与 SenseVoice 的一致率仅 41% → 校订稿不可用；改用 **SenseVoice × SeACo 双 funasr 模型对**后一致率 58~73%、**门诊 5 段（25 分钟）合计 206 处分歧点**——人工标注只需仲裁这 206 处，而非逐字听写约 3500 字。工具支持 `--engines "funasr,funasr:<SeACo模型ID>"` 同族双模型交叉。
- **质量守卫（引擎内置）**：转写结果自动检测重复循环（4-gram 重复 ≥3）与繁体输出（占比 >2%）→ warnings 警示"本段质量存疑，建议复听"，供下游（过程稿/抽取）判断是否降级处理。
- **热词表自动生长（纠错对沉淀，Phase ③ 上下文偏置）**：`tools/hotword_harvest.py` 扫描评测明细里的 `hotwords_applied`（规则有效性证据）与 `corrections`（LLM 纠错对），聚合为候选清单（频次 × 来源报告数）；人工审核（标 `approve: true`）后 `--merge` 写入热词表（自动备份）。首轮实测沉淀 9 条候选，患者F 纠错对入库后增至 **32 条**。
- **首个"沉淀→审核→合并→验证"闭环（已完成）**：三分类审核（批准 21 / 缓议 10 / 拒绝 1，记录见案例区 `热词审核记录.md`），热词表 **26 → 47 条**；bench 前后对比：患者F whisper 裸转写 CER 66.5%→**60.1%**、funasr 裸转写 88.1%→**86.2%** 且事实 11/12→**12/12**，彩排 funasr 裸转写 4.4%→**2.4%**，**无任何回归**。**关键量化结论：LLM 纠错的边际增益从 -9.6pp 降到 -3.2pp（whisper）、-2.8pp 降到 -0.9pp（funasr）——确定性热词规则接管了约 2/3 原由 LLM 承担的纠错量，最终精度持平**。这验证了"LLM 纠错 → 人工审核 → 确定性规则"的降本路径（更快、可审计、零边际成本），且缓议项（通过/有关/条子/行李/小屋/小指/腾市…）如实暴露了上下文相关风险，人工把关不可省。
- **模型规模实验（已完成，结论：否证）**：whisper-large-v3-turbo（1.6GB）患者F CER **79.4%**（small 66.5%）、事实 10/12（small 12/12）；门诊 1 仍幻觉、与 SenseVoice 一致率 47.2%（small 41.0%）。**换更大模型不解决方言/噪声问题**——与 §一"不做孤立方言模型、数据才是瓶颈"的判断一致，投入应落在标注与录音质量上。

**合规前置（已起草）**：《录音知情同意书模板》增补"转写数据用于院内模型优化"**独立同意**条款（§二.3/§三.4/§四.2/§六勾选栏：未勾选即不同意、可撤回、先脱敏、不出院），待医务科/伦理确认口径。

**引导运行结果（2026-10-16）**：归集 6 个真实案例（患者F 已评测；门诊 1-5 已落双份草稿待标注）+ 1 个合成回归用例；**真实音频总量 0.44 小时（微调门槛 50h 的 0.9%）**——数据飞轮已转起来，但**标注是当前唯一瓶颈**。

**新增"精确真值"回归用例（彩排录音，TTS 合成+逐轮标注，可作 CI 冒烟）**：

| 引擎 | CER | 净CER | 事实保留（15 项） |
|---|---|---|---|
| funasr SenseVoice + LLM 纠错 | **1.7%** | 1.7% | **15/15** |
| funasr SenseVoice（级联前） | 4.4% | 4.4% | 15/15 |
| whisper-small + LLM 纠错 | 7.5% | 7.6% | 12/15 |

- **与真实方言案例的结论互补**：清晰音频上 SenseVoice 显著更准（1.7% vs 7.5%），真实方言上 whisper+LLM 更稳（56.9% vs 85.3%）——**再次印证单例不能定选型**，必须多案例复选；
- 该用例 CER 里含"方言助词归一化差异"（参照写 喽/咧/俺，模型倾向规范化为 了/我），属可接受行为而非听错；LLM 级联在 SenseVoice 上净修 11 处、whisper 侧热词表净修 4 处（脓血便/阑尾×3）。

**顺带修复一个预置 bug**：`wav_duration_sec` 跳过未知 chunk 时 `f.seek(size)` 缺 `whence=1`（跳到绝对偏移），导致凡带 LIST 块的 WAV（afconvert/ffmpeg 转码产物）时长一律算 0——已修并回填语料库时长（`asr_ingest.py` 的同类实现是对的，未受影响）。

| 4 | **时间词错误** | "七点多"被 funasr 听成"两点多"；whisper 听成"聊点多"，**LLM 级联已实测修对**（聊点多→七点多）；funasr 的"两点多"属真实错听（非对照表可覆盖），建议抽取层对时间字段做"低置信复核"提示 |
| 5 | **角色分离缺失** | 本地引擎均无医/患分离（后处理标注）；cam++/3D-Speaker 为后续选项（funasr 管线内可挂，需与自研分段策略整合） |
| 6 | **离线交付镜像缺陷（待修）** | `deploy/offline/Dockerfile.llm-api` 的 `WITH_LOCAL_ASR=1` 走 alpine(musl) 基座，而 ctranslate2/torch **均无 musllinux 轮子**（PyPI 实测：ctranslate2 仅 manylinux/macosx/win，torch musllinux=0）——该构建路径预计失败且从未真构建过（交付包 images/ 为空，此前用 `--skip-images` 联调）。对策：本地 ASR 构建切 glibc 基座（python:3.12-slim + apt ffmpeg），并在打包机实测后再发版 |
| 7 | **模型迭代快** | 微调收益可能被新版基座抹平；微调时机定在"基座收敛"后（§一阶段③） |
| 8 | **LLM 级联的限流降级** | 批量评测实测触发 429（Too Many Requests）→ 管线按设计降级"保留原转写 + warnings 留痕"（不阻断）；批量场景建议串行/错峰或提高配额，报告里留意降级提示 |
| 9 | **模型下载网络** | 模型已缓存但 HuggingFace 不可达时（实测 MaxRetryError），whisper 适配器自动转离线加载重试；国内网络可设 `HF_ENDPOINT=https://hf-mirror.com`；**hf_hub 对镜像 302 重定向会报 FileMetadataError（实测）——大模型改用手动下载到本地目录 + `ASR_LOCAL_MODEL=<本地目录>` 加载**（turbo 验证即走此路径，绕过 hf_hub）；funasr 侧走 ModelScope（国内直连） |
| 10 | **whisper 在嘈杂门诊音频上崩溃** | 门诊 1/5 实测：幻觉 + 同句循环 + 繁体输出，`condition_on_previous_text=False` 与反循环参数（no_repeat_ngram=3 / repetition_penalty=1.15）均无干净改善，**去掉提示词也复现**（非提示词之过）；音频电平正常（RMS 0.066/峰值 0.63），属模型在噪声+重叠说话下的能力边界。对策：①质量守卫自动警示（已内置）；②门诊场景用 SenseVoice（实测稳健）；③住院场景 whisper-small 仍可用；④**whisper-large-v3-turbo 实测反而更差**——门诊 1 仍幻觉/触发放循环告警、与 SenseVoice 一致率 47.2%（small 41.0%）；患者F CER **79.4% vs small 66.5%**、事实 10/12 vs 12/12——**模型规模不是方言/噪声瓶颈的解**，正解是数据（标注→微调）+ 录音质量 + 语音增强前端 |
